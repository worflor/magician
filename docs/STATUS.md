# Status

The board by the door: what works, what stands between Magician and a fully unattended pipeline, and the loose ends. Not a plan. History is in [CHANGELOG.md](../CHANGELOG.md).

## What works

- **The whole loop.** Native readers for VPK, resources, KV3 (LZ4 and zstd), textures, meshes and cloth. 79 lint rules (M001 to M148; the mesh family is M100 to M148). Build, release, and install with a ledger and rollback. Drift and the patch-day check, with rig and engine sidecars, each mod compared from the last build a proof holds its bytes on. Grading (depth, identity, fair play, freshness, release gate, one reproducible record) with every judgement number in a policy. Proofs tied to bytes. The maker's mark. Scene patches. Release bundles and a static mod source with its pages. The MCP server, and a skill for agents that drive the CLI.
- **The game, driven.** One session driver for any mod, with the game bound to the seat that launched it, and patch day in game as one command: a vanilla pass where a build has no baseline, each mod's pass, one report, and a guarded `accept` that records the proof.
- **One program.** Every command answers `--help` and `--version`, exit codes have one meaning each (0 clean, 1 broken, 2 usage, 3 refused, 4 re-prove, 5 an update is available), the commands a script reads print one JSON document with `--json`, and the Python tools run through `magician` too. Locations resolve per machine (flag, environment, config file, Steam), so a fresh clone runs without editing code: `magician paths` shows what was found, `magician doctor` what is missing and how to fix it.
- **Updating is easy, and so is finding out.** `magician update --check` says whether there is a newer Magician and whether it would change judgement (grading rubric, built-in policy, lint rules), `magician update` installs it from a release or a git checkout and rolls back what fails, and a folder works as a source for machines with no internet. It runs only when asked ([README.md](../README.md), "Staying current"). Held by tests on scratch toolkits; no release has been cut yet.
- **A mod's folder is enough.** `magician new` starts one from the game's own data, `magician init` describes an existing pak, and inside the folder `check` gives the mod's one verdict and the other verbs need nothing after them.
- **Tested without the game.** `cargo test --workspace` runs on synthetic fixtures; two more tests grade real mods when the game and their paks are on the machine, and skip otherwise. The Python tools have their own suites. The Rust suite has been run on Ubuntu 24.04 as well. Every reader of bytes or text from outside is fuzzed (a short run in every `cargo test`, a long one on request; CONTRIBUTING.md), and the workspace passes `cargo clippy -- -D warnings` with overflow checks on in tests.
- **Used for real.** Three full hero skins are made with this toolchain. One is public: [Maid Lash](https://woflo.dev/deadlock-skins/maid-lash/), built, graded `S Costume`, proven on each build since its release and published as a Deadlock Mod Manager source. Two more are in production. The patch-day path has been through several real updates and a set of synthetic breakages ([PATCH-DAY.md](PATCH-DAY.md), "Drills").

## Between here and fully unattended

Roughly in the order an automation meets them.

- **The update has to be noticed.** Magician reads the installed build. Watching Steam, scheduling the check and sending the message are the host's job.
- **The in-game pass needs a desktop.** The harness types with SendInput and captures the window, so it needs an interactive Windows session with the game in front. It cannot run as a service.
- **The pictures need a reader.** A pass ends in contact sheets, and a proof is recorded only after something that can see has read them. Comparing stills between passes was measured and does not work ([PATCH-DAY.md](PATCH-DAY.md), "Why stills are not compared"); it would take scenarios that freeze the hero at a known frame of a known clip.
- **Grading has rubrics for hero mods only** (character, variant, kit). A map, HUD or music mod is `not graded`, and says so.
- **Some identity is declared, not measured.** A new voice identity counts only when `mod.toml` declares it (`[identity] voice = "new"`), and a replaced name logo counts as a rename only through the mod's name in `mod.toml`: bytes can't tell a new voice from a treatment, or read a logo.

## Loose ends

- **What the mesh family does not judge.** A model is measured as its default body-group choice against the default hitbox set; another choice and its own hitbox set are not looked at. Animation is not decoded, so nothing is judged in motion: clip-to-clip continuity, a spring-driven bone keyed to move while its parent is still, a cloth goal pose strained by a clip. Sound is compared by the length and envelope peak the compiler stored, not by loudness: that needs the MP3 decoded. An albedo step across a UV seam of one material (a repainted panel that kept a baked shadow) has no rule.
- **Cloth has one rule, on purpose.** Rules for a node resting inside a collision shape, a shape that fits between two nodes, a rod at odds with the rest pose and a settling time were measured on Valve's 47 heroes before being written, and Valve's own cloth breaks every one of them ([reference/engine.md](reference/engine.md), Cloth). Only a comparison with Valve's group at the same place holds, which is what M141 does.
- **An engine comparison needs two captured builds.** The engine sidecar is written when a build is captured while installed, so a patch from a build captured before the sidecar existed reads `no engine record`.
- **Session paths not run against the live game.** `session film` (a SourceTV take filmed from free cameras, which needs a take's tracks through Boon) and `session --pak` (a candidate pak over the mod's slot) are held by tests on synthetic data and a scratch game. `up`, `run`, `down`, `qa`, and `--vanilla` with `--restore` run in the game.
- **A scaffold has not been released.** `magician new` was run on two heroes and its package passes the bundler in a fixture; a `release` from a fresh scaffold needs the addon linked into the CSDK and has not been done end to end.
- **Releases are unproven end to end.** `tools/make-release.ps1` was run into a scratch folder and `update --check` and `update` run against its output (Windows). `.github/workflows/release.yml` has not run on GitHub, and the Linux asset has never been built or run: the code paths that pick an asset by platform and refuse a source without one are tested, a real Linux update is not. A crash in the middle of a swap is not handled beyond refusing the next update and saying where the old files are. The default source, the repository's latest release, answers "could not check" until the repository is public and a release exists.
- **CI has not completed a run on GitHub.** `.github/workflows/ci.yml` was proven locally step by step, not on a runner. `cinema/test_scene.py` needs ffmpeg and is left out of it.
- **Linux is built and tested, not driven.** The workspace builds and its suite passes on Ubuntu 24.04, and the player scene installer is proven there. The seat check reads `/proc` (the game under Proton) and refuses when it can't tell; no install has been run against a real game on Linux, and the `/proc` read is held by a unit test on synthetic command lines.
- **`mod.toml` is read line by line.** Flat tables of strings, numbers and lists are all the readers take; nested TOML is not.
- **Source 2 Viewer credit.** Its MIT licence asks for its notice if its binaries ship, and the project asks for a "Powered by Source 2 Viewer" credit. This repository ships none of its binaries; where to credit it is the author's call.
- **Engine facts not yet measured** are marked as such in [reference/engine.md](reference/engine.md) (bone-count effects, cloth collision layers).
