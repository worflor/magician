# Status

The board by the door: what works, what stands between Magician and a fully unattended pipeline, and the loose ends. Not a plan. History is in [CHANGELOG.md](../CHANGELOG.md).

## What works

- **The whole loop.** Native readers for VPK, resources, KV3 (LZ4 and zstd), textures, meshes and cloth. 80 lint rules (M001 to M149; the mesh family is M100 to M148). Build, release, and install with a ledger and rollback. Drift and the patch-day check, with rig and engine sidecars, each mod compared from the last build a proof holds its bytes on. Grading (what a mod makes its own, identity, broken, fair play, freshness, release gate, one reproducible record) with every judgement number in a policy. Proofs tied to bytes. The maker's mark. Scene patches. Release bundles and a static mod source with its pages. The MCP server, and two skills for agents: one to drive the CLI on a mod, one to bring a mod made without Magician under it.
- **The game, driven.** One session driver for any mod, with the game bound to the seat that launched it, and patch day in game as one command: a vanilla pass where a build has no baseline, each mod's pass, one report, and a guarded `accept` that records the proof.
- **One program, on Windows and Linux.** Every command answers `--help` and `--version` and refuses an option that is not its own before anything runs, exit codes have one meaning each (0 clean, 1 broken, 2 usage, 3 refused, 4 re-prove, 5 an update is available), the commands a script reads print one JSON document with `--json`, and the Python tools run through `magician` too. Locations resolve per machine (flag, environment, config file, Steam), so a fresh clone runs without editing code: `magician paths` shows what was found, `magician doctor` what is missing and how to fix it.
- **Updating, only when asked.** `magician update --check` says whether there is a newer Magician and whether it would change judgement; `magician update` applies it to a release install or a git checkout and puts back what fails ([README.md](../README.md#staying-current)). Held by tests on scratch toolkits; no release has been cut yet.
- **A mod's folder is enough.** `magician new` starts one from the game's own data, `magician init` describes an existing pak, and inside the folder `check` gives the mod's one verdict and the other verbs need nothing after them.
- **Tested without the game.** `cargo test --workspace` runs on synthetic fixtures; two more tests grade real mods when the game and their paks are on the machine, and skip otherwise. The Python tools have their own suites. Both run on Windows and on Linux (Ubuntu 24.04), the harness's X11 side against a window of its own. Every reader of bytes or text from outside is fuzzed (a short run in every `cargo test`, a long one on request; CONTRIBUTING.md), and the workspace passes `cargo clippy -- -D warnings` with overflow checks on in tests.
- **Used for real.** Three full hero skins are made with this toolchain. One is public: [Maid Lash](https://woflo.dev/deadlock-skins/maid-lash/), built, graded `Costume (look, effects, sound)`, proven on each build since its release and published as a Deadlock Mod Manager source. Two more are in production. [SHOWCASE.md](SHOWCASE.md) shows two of the three in Magician's own output. The patch-day path has been through several real updates and a set of synthetic breakages ([PATCH-DAY.md](PATCH-DAY.md), "Drills").

## Between here and fully unattended

Roughly in the order an automation meets them.

- **The update has to be noticed.** Magician reads the installed build. Watching Steam, scheduling the check and sending the message are the host's job.
- **The in-game pass needs a desktop.** The harness types into the game and captures its window, so it needs a logged-in desktop with the game in front: an interactive Windows session, or an X display on Linux. It cannot run as a service.
- **The pictures need a reader.** A pass ends in contact sheets, and a proof is recorded only after something that can see has read them. Comparing stills between passes was measured and does not work ([PATCH-DAY.md](PATCH-DAY.md), "Why stills are not compared"); it would take scenarios that freeze the hero at a known frame of a known clip.
- **Grading has rubrics for hero mods only** (character, variant, kit). A map, HUD or music mod is `not graded`, and says so.
- **Some identity is declared, not measured.** A new voice identity counts only when `mod.toml` declares it (`[identity] voice = "new"`), and a replaced name logo counts as a rename only through the mod's name in `mod.toml`: bytes can't tell a new voice from a treatment, or read a logo.

## Loose ends

- **What the mesh family does not judge.** A model is measured as its default body-group choice against the default hitbox set; another choice and its own hitbox set are not looked at. Animation is not decoded, so nothing is judged in motion: clip-to-clip continuity, a spring-driven bone keyed to move while its parent is still, a cloth goal pose strained by a clip. Sound is compared by the length and envelope peak the compiler stored, not by loudness: that needs the MP3 decoded. An albedo step across a UV seam of one material (a repainted panel that kept a baked shadow) has no rule.
- **Cloth has one rule, on purpose.** Rules for a node resting inside a collision shape, a shape that fits between two nodes, a rod at odds with the rest pose and a settling time were measured on Valve's 47 heroes before being written, and Valve's own cloth breaks every one of them ([reference/engine.md](reference/engine.md), Cloth). Only a comparison with Valve's group at the same place holds, which is what M141 does.
- **An engine comparison needs two captured builds.** The engine sidecar is written when a build is captured while installed, so a patch from a build captured before the sidecar existed reads `no engine record`.
- **A cloth candidate that failed the corpus.** A loose chain lighter than the hero's fall (`sv_gravity` 800) rises while he is airborne; a skin's headband ribbons did, in game. Measured with the solver model on Valve's cloth (`magician corpus`), the same test fires on 59 of Valve's 200 groups, so it is not a rule: lint cannot yet tell a ribbon that floats from Valve's own short danglers, and an in-game jump is the check. M141 also grew louder on that skin's fixed ribbons (gravity raised twelvefold, ringing predicted at 3.6 Hz) without the game showing it: the oscillator model treats gravity as stiffness only.
- **Session paths not run against the live game.** `session film` (a SourceTV take filmed from free cameras, which needs a take's tracks through Boon) is held by tests on synthetic data. `up`, `run`, `down`, `qa`, `--vanilla` with `--restore`, and `--pak` with `--restore` (and `--force`) run in the game. A mod that floods the console (one printed a camera-pivot warning every frame, 26,000 lines in three minutes) can keep `console.py`'s probe from seeing the console open, so a scenario fails where the next one runs.
- **The witness reads what the engine logs, no more.** A missing attachment the game falls back on (an overhead bar), an opening, a silhouette or a colour logs nothing: those findings stay a frame's, named with the probe, and someone looks. A level (how loud, how far) is a file fact; the log says a sound started, not how it sounded.
- **A scaffold has not been released.** `magician new` was run on two heroes and its package passes the bundler in a fixture; a `release` from a fresh scaffold needs the addon linked into the CSDK and has not been done end to end.
- **Releases are unproven end to end.** `tools/make-release.ps1` was run into a scratch folder on Windows and on Linux (PowerShell 7), and `update --check` and `update` run against its output on each, from a folder. `.github/workflows/release.yml` has not run on GitHub. A crash in the middle of a swap is not handled beyond refusing the next update and saying where the old files are. The default source, the repository's latest release, answers "could not check" until the repository is public and a release exists.
- **Nothing has gone to the real Nexus Mods.** `publish nexus` is held by tests against a fake Nexus that follows the schema of Nexus's own upload action. No upload has met their servers: there was no key and no page. The first real one is also the first look at whether a draft page takes a new file, its text and its changelog (the schema does not say), and at how Nexus splits a changelog into entries.
- **CI has not completed a run on GitHub.** `.github/workflows/ci.yml` was proven locally step by step, on Windows and on Ubuntu, not on a runner. `cinema/test_scene.py` needs ffmpeg and is left out of it.
- **Linux has not met the game.** Everything that reads or writes files is proven there, compiling under Wine and grading with the Linux viewer included ([README.md](../README.md#platforms) has the table). What has not run on Linux is the game itself under Proton: the seat check's reading of a real Proton process, the harness and the film kit against the game's window (XWayland or gamescope), and launching through `steam -applaunch`. It takes a Linux desktop with a GPU, or a Steam Deck in desktop mode, signed in to Steam with the game installed; `python ingame/prove_harness.py` there runs the whole harness once and writes a report.
- **The viewer's GUI is Windows only.** `tools/s2v_mcp.py start` needs it; under Wine it opens but its MCP server does not listen.
- **`mod.toml` is read line by line.** Flat tables of strings, numbers and lists are all the readers take; nested TOML is not.
- **Engine facts not yet measured** are marked as such in [reference/engine.md](reference/engine.md) (bone-count effects, cloth collision layers).
